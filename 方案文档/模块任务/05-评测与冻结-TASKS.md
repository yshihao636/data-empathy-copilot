## 本轮设计与后续执行边界

- EVAL-T001：先按[设计边界](../04-评测协议-详细.md#benchmark-design)完成人工走读和覆盖缺口登记；设计完成不代表集合、gold 或冻结完成。
- EVAL-T002：按[三层验证](../04-评测协议-详细.md#evaluation-layers)区分契约、单点和状态回放；记录真实事件引用、预算/重置条件、重试/降级链；状态回归引用 UI 验收，不改变 AGENT-T004 的最终运行前置。
- EVAL-T003：按[安全门槛](../04-评测协议-详细.md#gates)分列阻断项与质量，不设总分；可选重复实验严格遵循[可靠性口径](../04-评测协议-详细.md#reliability)，未运行不填数。
- EVAL-T004：按[报告契约](../04-评测协议-详细.md#report-contract)披露小样本、主案例曝光、适用范围和未执行项；LLM 裁判只作辅助，按[裁判分工](../04-评测协议-详细.md#judging)留证。

## 证据层级约定

- 评测协议、任务和检查项是设计定义，不是运行结果。
- 当前未有集合文件、gold、四组运行器或真实报告；在这些产物生成前，不得写“评测完成”或报告效果收益。
- A/B 阶段验证报告不是四组对照结果，也不能替代冻结集、boundary set 或 retention set 证据。
